Desarrollo de software

El código limpio es una forma de respeto

El software legible no es solo una preferencia de estilo. Es un compromiso con las personas que tendrán que usarlo, revisarlo, depurarlo y mantenerlo.

8 de enero de 2024 · 6 minutos de lectura

Cuando empecé a programar, pensaba que escribir código limpio consistía en respetar ciertas convenciones para los nombres y mantener cortas las funciones. Esas prácticas importan, pero apuntan hacia una idea más amplia: el código también es comunicación.

Escribimos instrucciones para las computadoras, pero a la vez dejamos explicaciones para otras personas. Quizás alguien del equipo tenga que ampliar una función el mes que viene. Tal vez otra persona deba diagnosticar un problema en producción a altas horas de la noche. Dentro de seis meses, nosotros mismos podemos ser quienes lean el código con desconcierto.

La claridad es una elección

Un nombre como getUserById() exige apenas un poco más de esfuerzo que una abreviatura, pero evita una duda a cada persona que lea el código después. Una función bien enfocada vuelve más seguro cualquier cambio. Un comentario breve puede explicar por qué existe una decisión poco habitual.

Ninguna de estas elecciones resulta extraordinaria por sí sola. Juntas determinan si un repositorio se siente como una herramienta compartida o como un acertijo que todos deben resolver de nuevo.

La ética de la mantenibilidad

La filosofía me ha hecho más consciente de que las decisiones técnicas afectan a otras personas. El código desordenado traslada el esfuerzo que ahorramos hoy a quien tendrá que mantenerlo mañana. Una interfaz inaccesible hace que el usuario pague el costo de un atajo de diseño. Un sistema que oculta sus concesiones dificulta que el equipo tome decisiones responsables.

El buen código respeta el tiempo, la atención y las limitaciones de la próxima persona que se encuentre con él.

Esto no significa que todo proyecto necesite una arquitectura perfecta. Significa que las personas afectadas por nuestro trabajo deben formar parte del cálculo.

Limpio no significa ingenioso

Buscar calidad encierra una paradoja: la obsesión por encontrar la abstracción perfecta puede volver el software más difícil de entender. El código limpio no es el que acumula más patrones, emplea menos líneas o adopta las herramientas más recientes. Es el que comunica su propósito y permite realizar los cambios que el proyecto de verdad necesita.

A veces una función más larga cuenta una historia más clara. A veces mantener una línea repetida es más sencillo que introducir una abstracción prematura. El criterio importa más que las reglas mecánicas.

Principios que intento practicar

Escribe para quien venga después

Da por hecho que alguien que no conoce la tarea tendrá que comprender el código. Haz evidente el camino importante y pon a cada cosa un nombre que exprese lo que significa.

Explica la decisión, no la sintaxis

El código suele mostrar qué hace. Los comentarios aportan más cuando conservan el contexto: la limitación, la concesión o la necesidad del usuario que motivó una elección.

Deja el lugar mejor de como lo encontraste

Las mejoras pequeñas se acumulan. Aclarar un nombre o eliminar una rama obsoleta reduce fricción sin convertir cada tarea en una reescritura completa.

Invita a que te den opiniones

El código legible mejora mediante la colaboración. Una revisión no es solo una barrera de control; también permite comprobar si una idea resulta tan clara para otra persona como para quien la escribió.

El software es una actividad humana

Los programas se ejecutan en máquinas, pero las personas imaginan, construyen, mantienen y utilizan el software. El código limpio reconoce esa realidad. Considera que la claridad forma parte de la calidad y que el mantenimiento forma parte del diseño.

La meta no es la perfección. La meta es facilitar y aclarar el trabajo de la siguiente persona, y construir sistemas dignos de su confianza.
